# 썰판 제작소 · 인스타 이미지 제작기

기존 제작소의 **본문 작성 바로 아래 → 미리읽기를 한 장씩**에서 사용합니다. 기존 표지·원고 작성/게시 기능은 유지합니다.

## 사용

1. 광고 전 공개 범위를 기존 본문 경계로 정합니다.
2. **미리읽기로 이미지 만들기**를 누릅니다. 표지 + 본문 + 선택적인 마지막 안내가 생성됩니다.
3. 모든 장에 적용할 크기·템플릿·글자 크기·줄 간격을 정합니다. 사진이 필요하면 공통 이미지 또는 장별 이미지를 넣고 **상단 이미지 + 본문**을 선택합니다.
4. 작은 카드를 눌러 문구를 직접 수정합니다. 커서에서 다음 장으로 나누기, 다음 장과 합치기, 현재 카드 내용 다시 나누기를 지원합니다.
5. **전체 이미지 ZIP**으로 개별 PNG와 캡션을 저장합니다. Instagram 업로드는 직접 진행합니다.

기본 1080×1920, 선택 1080×1350. 표지/본문/마지막 장이 모두 같은 크기입니다. 텍스트가 넘치거나 필요한 사진이 없으면 잘린 파일을 내보내지 않고 경고합니다. 최초 자동 분할은 미리읽기 내용을 그대로 보존합니다. 카드에서 직접 수정한 내용은 원고 본문을 덮어쓰지 않습니다.

## 범위와 저장

광고 전 `before-content`만 읽습니다. 광고 후 본문은 읽거나 저장하지 않습니다. 제목 또는 미리읽기 범위가 바뀌면 예전 카드 내보내기가 잠기며, **현재 미리읽기 다시 반영**으로 갱신합니다. 이때 공통 스타일·표지·공통 이미지는 유지하고 본문은 새 범위로 다시 나눕니다.

편집본은 IndexedDB에 백업하고, 기존 제작소 세션으로 서버에 자동 저장합니다. 다른 기기에서 같은 원고 제목과 미리읽기 범위를 열고 만들기를 누르면 저장본을 불러옵니다. 저장 식별자는 제목+미리읽기의 SHA-256입니다. 원고 저장과 카드 저장은 별도이며 상태 문구를 확인해야 합니다. 두 기기가 동시에 수정하면 버전 충돌을 알리고 자동 덮어쓰기를 막습니다. JSON 작업파일 내보내기/불러오기도 지원합니다.

사진은 직접 첨부하는 첫 버전입니다. 분할·미리보기·PNG/ZIP 생성에는 AI API를 호출하지 않습니다. 유료 AI 삽화 생성이나 Instagram 계정 자동 게시를 구현했다고 간주하지 마세요.

## 개발/배포

- `studio-carousel.js`: 기존 DOM에 추가하는 편집기, 기기/서버 저장
- `studio-carousel-core.mjs`: 동일 Canvas 렌더러, 정확한 분할, ZIP 생성
- `studio-carousel-contract.mjs`: 클라이언트/서버 공통 검증
- `ssul-instagram-api.mjs`: 기존 Worker 세션/Origin 검증 뒤 호출되는 어댑터
- `supabase/functions/ssul_instagram`: 기존 `ssul_studio`에 세션을 재검증한 뒤에만 DB 접근
- `public.ssul_instagram_decks`: RLS, 공개 역할 접근 차단, 버전 비교 저장 RPC
- `scripts/package-carousel.py`: 기존 접근 보호 빌드 뒤 추가 파일/모듈을 배포물에 포함

공통 글꼴은 Pretendard v1.3.9 CDN을 사용합니다. 로드 실패 시 기기 기본 글꼴로 몰래 출력하지 않고 재시도를 안내합니다. 프로젝트별 원고/이미지 데이터를 외부 AI로 보내지 않습니다.

## 확인 범위

`node --test tests/carousel.test.mjs`: 21개 통과. 실제 Chromium에서 PNG/ZIP 생성, 수동 수정, 범위 변경 차단, 사진/규격 변경, 좁은 화면, 두 편집기의 버전 충돌 6개 시나리오 확인.

브라우저 검증 환경에서는 네트워크가 제한되어 폰트와 서버 API를 테스트 대역으로 공급했습니다. 실제 Supabase의 로그인 후 저장 왕복과 실제 휴대폰 환경을 검증했다는 뜻은 아닙니다. DB RLS 및 anon/authenticated 접근 차단은 배포된 프로젝트에서 확인했습니다. 기존 게시글과 원고 데이터는 변경하지 않았습니다.
