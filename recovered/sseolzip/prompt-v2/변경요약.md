# 변경 요약

## 삭제
- 목표·최소 글자 수, 허용 오차, 원문 대비 증감률, 광고 전후 35~60% 비율
- 리듬 규칙 전체: 다섯 자 이하 문장 필수, 스물다섯 자 이상 문장 필수, 연속 세 문장 글자 수 비교, 한 문장 문단 필수
- 자체 점검의 대응 조항 3개
- 인물 최소 두 명의 관계·나이·직업 변경 의무
- 장소·소품 교체 의무
- 연속 다섯 어절 일치 금지
- 무관한 여담 삽입, 불명확한 수량의 숫자화, 완충 표현을 단정으로 바꾸기
- `options.length`를 값 존재만으로 분량 지시로 읽는 처리

## 교체
- 분량 판단 기준을 지정하신 문장으로 대체. 핵심 사건·인과, 인물 관계, 대사의 역할, 감정 전환, 반전·결말을 전달하면 종료하고, 요약도 늘리기도 하지 않으며 표현상 중복만 정리
- 끊는 위치를 "이야기 안에 이미 있는 전환점"으로. 끊을 자리를 만들려고 사건이나 반응을 추가 금지
- `options.length` → `options.lengthMode`(`source`/`custom`) + `options.lengthRequest`. custom이고 요청 문구가 있을 때만 전달
- 원문 보존 검증을 "자동 검증 불가"에서 "일부 이상 징후는 탐지 가능하나 완전한 의미 보존은 보장 불가"로. 항목별 가능한 검사와 한계를 표로 분리
- `target` 누락·오류를 서버 400 거절로. 프롬프트는 도달 시 원문 그대로 반환하는 방어 동작만 유지
- 익명화를 대응표 기록으로. 이름만 바꾸고 관계·동기·인과는 유지

## 신설
- 파생 순서: 본문 완성 후 부가 필드 파생. 표지 때문에 본문을 고치지 않음
- 부가 필드 단독 보정: `titles` 포함, 해시태그, `coverDetail` 위반은 `action="social"` 재호출로 해당 필드만 수정. 전체 재생성 금지
- `hook` 줄 수를 권장으로 확정. 검증은 경고만, 실제 맞음 여부는 렌더링 단계에서 확인
- 자동 절단 6경로 목록과 대체 처리
- 한도 3종 구분: 애플리케이션 제한 / 요청 용량 / 출력 토큰 한도. `stop_reason="max_tokens"`는 미완성 처리하고 자동 요약 금지
- `imageText`를 표시용 발췌로 명시. OCR 전체 결과 별도 보관, 잘림 여부 상태 필드
- 부분 수정에서 분량·원문 보존·문체 점검을 허용 범위 안으로 한정
- `cleanDraft`, `promptFor` 수정 필요 기록

## 스키마
필수 여부, 타입, 빈 값 검사는 그대로 유지. `maxLength`는 애플리케이션 제한이며 분량 목표가 아니라는 설명을 각 필드에 추가. 본문 분량 목표는 어느 스키마에도 없음.
