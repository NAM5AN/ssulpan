# 사이트 코드에서 추가로 반영할 항목

## 1. 요청 페이로드
- `action` 필드 추가: `"generate" | "rewrite" | "social"`. 미전달 시 서버에서 `"generate"`로 채워 보낸다.
- `target` 필드 추가: `action="rewrite"`일 때만 `"before" | "after"`. 누락이거나 다른 값이면 400으로 거절한다. 모델에 임의 판단을 맡기지 않는다.
- `options.length` 제거. 대체 필드는 아래 2를 따른다.

## 2. 분량 요청 판별

기본 UI에는 분량 입력을 두지 않는다. 축약·확장은 `notes`와 `rewriteInstruction`에 사용자가 직접 쓴 요청으로만 반영한다.

`options.length`를 호환용으로 유지한다면 `options.lengthMode`를 함께 둔다.

| lengthMode | 처리 |
|---|---|
| `"source"` | 원문에 맡김. 분량 지시를 모델에 전달하지 않는다 |
| `"custom"` | 사용자가 직접 지정을 켜고 요청을 입력한 경우에만. `options.lengthRequest`로 그 요청 문구를 전달한다 |

아래는 전부 분량 지시로 전달하지 않는다.
- `lengthMode` 누락
- `lengthMode="source"`
- `lengthMode="custom"`이지만 요청 문구가 비어 있음
- 예전 원고에서 불러온 길이 기본값
- UI가 초기값으로 채워 넣은 숫자

명시적 요청이 있더라도 결과 글자 수를 검사해 실패 처리하거나 자동 재생성하지 않는다.

### 수정이 필요한 경로
`cleanDraft`와 `promptFor`는 현재 `options.length`를 제거한다. 선택적 지원을 유지하려면 두 경로 모두 수정해야 한다.
- `cleanDraft`: `lengthMode`와 `lengthRequest`를 보존하도록 화이트리스트 수정
- `promptFor`: `lengthMode="custom"`이고 요청 문구가 있을 때만 `options.lengthRequest`를 페이로드에 포함

## 3. 도구 3종 분리
`action`마다 다른 도구 하나만 정의해 전달한다. strict 모드는 `maxLength` / `minItems` / `uniqueItems`를 지원하지 않으므로 도구 스키마에는 타입과 `required`만 넣고, 나머지는 서버 검증에서 처리한다.

| action | 도구 반환 필드 |
|---|---|
| generate | 13개 전부 |
| rewrite | `text` |
| social | `titles`, `hook`, `coverDetail`, `caption`, `hashtags` |

## 4. 생성 결과 검증

### 실패로 처리하는 것
- 필수 필드 누락
- `imageText` 외 필드의 빈 값
- 타입 불일치, 정의되지 않은 추가 필드

### 부가 필드만 보정하는 것
아래가 어긋나면 해당 필드만 다시 만들도록 `action="social"`로 재호출한다. 같은 전체 생성 요청을 다시 돌리지 않는다. 본문은 그대로 고정한다.
- `titles.includes(title)` 미충족
- `hashtags`가 5개가 아니거나, 중복이 있거나, `#썰집`·`#썰`이 빠졌거나, `#`로 시작하지 않는 항목이 있음
- `coverDetail` 40자 초과

### 경고만 남기는 것
- `hook` 줄 수가 3~4줄을 벗어남. 이는 권장 기준이며 실패 조건이 아니다. 실제로 표지에 들어가는지는 렌더링 단계에서 텍스트 박스 오버플로로 확인한다.

## 5. 분량 검증 없음
본문 길이는 검증 대상이 아니다. 아래를 모두 제거한다.
- `options.length` 대비 합계 글자 수 비교, 허용 오차 검사
- 최소 글자 수 미달 검사
- 원문 대비 증감률 검사
- `beforeContent` 비율 검사
- 길이를 이유로 한 재생성, 실패 처리, 경고 노출
- 저장된 프롬프트, 프롬프트 생성 지침, 재시도 문구에 남아 있는 이전 분량 정책 문장

## 6. 원문과 본문을 자동으로 자르지 않기

아래 경로에서 조용한 잘림이 발생한다. 전부 제거하거나 명시적 처리로 바꾼다.

| 경로 | 현재 | 변경 |
|---|---|---|
| URL 원문 가져오기 | 100자 미만이면 거절 | 짧은 원문도 정상 입력이다. 거절 대신 사용자에게 확인만 받는다 |
| 원문 + OCR 합치기 | `slice(0, 50000)` | 자르지 않는다. 용량 초과는 아래 별도 처리 |
| `string` 정규화 | 길이 상한 절단 | 절단 제거 |
| `cleanDraft` | 본문 절단 | 절단 제거 |
| `validateResult` | 초과분 절단 후 통과 | 절단 없이 초과 여부만 보고 |
| 입력창 | `maxlength` 속성 | 제거하거나 실제 저장 한도에 맞춘다 |
| 자동 저장 / 복원 / 게시 / 미리보기 | 각기 다른 상한으로 절단 | 상한을 한 곳에서 관리하고 절단하지 않는다 |

용량이 실제로 초과되면 기존 원문과 원고를 보존한 채 사용자에게 알린다. 조용히 잘라 저장하지 않는다.

`imageText`는 표시용 발췌다. OCR 전체 결과를 별도 필드에 보관하고, `imageText`가 이후 작업의 유일한 원문이 되지 않도록 한다. 잘림 여부는 본문에 `[이하 생략]`을 넣는 것과 별개로 불리언 상태 필드로 관리한다.

## 7. 한도의 구분
아래 셋은 성격이 다르다. 하나로 뭉뚱그리지 않고, 어느 것도 본문 분량 목표로 쓰지 않는다.

| 구분 | 예 | 성격 |
|---|---|---|
| 애플리케이션 제한 | `imageText` 8,000자, `beforeContent`·`afterContent` 60,000자 | 우리가 정한 값. 근거를 확인하고 필요하면 조정한다 |
| 요청 용량 | 이미지 개수, 페이로드 크기 | 초과 시 요청 자체가 실패한다 |
| 출력 토큰 한도 | `max_tokens` | 응답이 중간에 끊긴다 |

`stop_reason`이 `max_tokens`인 응답은 미완성으로 처리한다. 사용자에게 알리고 한도를 올려 재시도한다. 이를 해결하려고 원문을 자동 요약하거나 본문을 잘라 저장하지 않는다.

## 8. 원문 보존 검증

일부 이상 징후는 탐지할 수 있지만 완전한 의미 보존은 보장할 수 없다. 검사의 기준은 보존된 원문이다. 생성 결과와 함께 만들어진 `storyBible`만으로 원문 보존을 판정하지 않는다.

| 항목 | 가능한 검사 | 한계 |
|---|---|---|
| 사건·인과 | 원문에서 뽑은 사건 키워드가 결과에 나타나는지 | 표현이 바뀌면 키워드로 잡히지 않는다. 인과가 뒤집혔는지는 문자열로 알 수 없다 |
| 인물 관계 | 익명화 대응표로 원문 이름과 결과 이름을 짝지어 등장 여부 비교. 대응표에 없는 새 이름 탐지 | 관계나 입장이 바뀌었는지는 판정 불가 |
| 중요한 대사 | 원문 따옴표 구간 수와 결과 따옴표 구간 수 비교 | 표현을 새로 쓰므로 일치하지 않는 것이 정상이다. 의미와 역할 보존은 판정 불가 |
| 감정 전환 | 없음 | 자동 탐지 불가 |
| 반전·결말 | 원문 후반부 고유명사·수치가 결과에 남아 있는지 | 반전의 논리가 유지됐는지는 판정 불가 |

대사 개수, 인물 수, 문장 수의 차이만으로 실패 처리하거나 재생성하지 않는다. 재구성 과정에서 달라지는 것이 정상이다.

이상 징후가 잡히면 문제 후보로만 표시하고, 원문의 해당 구간과 결과의 해당 구간을 나란히 제시해 사람이 판단하게 한다.

## 9. rewrite 처리
- 응답 `text`를 `target` 필드에 통째로 덮어쓴다. 병합하지 않는다
- 응답이 입력 원문과 완전히 동일하면 "변경 없음"으로 처리한다. 모델이 수정 불가 시 원문을 그대로 반환하도록 되어 있으므로 이것이 실패 신호다
- rewrite 응답으로 다른 12개 필드를 갱신하지 않는다
- 지정 범위가 있었다면 원문과 diff를 떠서 범위 밖 변경을 확인한다. 변경이 있으면 적용하지 않고 사용자에게 보여준다
- 길이 변화는 검사하지 않는다

## 10. 재시도
검증 실패 시 같은 요청에 실패 사유를 덧붙여 1회 재호출한다. 2회 연속 실패하면 사용자에게 노출한다.

- 부가 필드 문제는 `action="social"`로 재호출한다
- 재시도 사유에 분량을 넣지 않는다
- `stop_reason`이 `max_tokens`인 경우는 검증 실패가 아니라 한도 문제로 처리한다

## 11. 프롬프트로 보장되지 않는 것
지침에 적혀 있어도 모델이 어길 수 있다. 서버에서 검사한다.
- 해시태그 개수와 중복
- `title`의 `titles` 포함
- `coverDetail` 40자
- 필수 필드의 빈 값
- rewrite에서 지정 범위 밖 보존

## 12. UI
- 분량 입력을 기본 화면에서 제거한다. 유지한다면 "직접 지정" 토글을 꺼진 상태로 두고, 켠 경우에만 `lengthMode="custom"`으로 보낸다
- "목표 글자 수", "권장 분량" 안내 문구를 제거한다
- 글자 수를 표시하더라도 목표 대비 달성률이나 경고 색상은 붙이지 않는다
- 원문 입력창의 `maxlength`를 제거한다
